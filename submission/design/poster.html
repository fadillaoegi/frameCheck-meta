Does the build
match the design?

FrameCheck lays a screenshot of the build over the design export and asks Meta Muse Spark what went wrong: elements that went missing, text that got cut off, things that moved. Every finding comes with a box on both images, and a person decides what is real.

How it works

Five steps, one screen each

01

Capture

Design export and build screenshot at the same viewport and pixel ratio.

02

Pair

Upload both, add a note on what matters on the page.

03

Analyse

One Muse Spark request with both images returns structured findings.

04

Review

Zoom both images to the same spot; accept, or reject with a reason.

05

Export

Markdown for the pull request, JSON for your tools.

Built on Meta Muse Spark

Model output you can check

  • Strict JSON schema output: category, summary, check step, a box per image.
  • Coordinate contract: the model's 0–1000 grid is mapped back to original pixels.
  • Untrusted by default: each finding is checked against its category's evidence rules.
  • Prompt-safe notes, a request cap, duplicate detection and token accounting.
  • Honest origins: Muse Spark, fixture and mock runs are always labelled.
